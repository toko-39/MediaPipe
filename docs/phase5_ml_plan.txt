============================================================
Phase 5: 学習ベースへの移行（未実施・計画）
============================================================
作成日: 2026-11-10
状態: 未実施。ルールベースで精度不足の動作が出た場合に実施する。

■ 目的
  ルールベースの判定器では精度が出ない動作について、
  Phase 2 の記録データを使って時系列分類モデルを学習し、
  判定器を置き換える。

■ 前提
  - MediaPipe による特徴量抽出はそのまま使う
  - 置き換えるのは detectors/ 内の判定ロジック部分のみ
  - 全動作を一括で置き換える必要はなく、精度が低い動作だけ対象にする

■ 手順

  1. データ収集
     - Phase 2 の記録機能(main.py の r キー)でラベル付きデータを集める
     - 各動作を 50〜100 回以上、「何もしていない(none)」も同量以上
     - 複数セッション、可能なら複数人で記録

  2. データの前処理
     - CSVを読み込み、1.5秒(約45フレーム)のスライディングウィンドウで切り出す
     - 各ウィンドウにラベルを付与（ウィンドウ内で最も多いラベルを採用）
     - 使用する特徴量の列:
       head_pitch, head_yaw,
       left_elbow_angle, right_elbow_angle,
       left_wrist_x, left_wrist_y, right_wrist_x, right_wrist_y,
       left_hand_wrist_x, right_hand_wrist_x,
       left_fingertip_avg_x, right_fingertip_avg_x,
       left_palm_normal_y, right_palm_normal_y,
       left_hand_size, right_hand_size
     - 欠損値(手が映っていないフレーム等)は 0 埋めまたは前方補完

  3. モデルの候補

     (a) 統計量 + Random Forest（最も単純）
         - ウィンドウ内の各特徴量の mean, std, min, max, range を計算
         - 折り返し回数も特徴量に入れる
         - scikit-learn の RandomForestClassifier で学習
         - 利点: 実装が簡単、学習が速い、解釈しやすい
         - 欠点: 時系列の形状パターンは捉えにくい

     (b) 1D-CNN（軽量で高速）
         - 入力: (ウィンドウ長, 特徴量数) の2次元配列
         - 構成例:
           Conv1D(32, kernel=5) → ReLU → MaxPool
           → Conv1D(64, kernel=3) → ReLU → GlobalAvgPool
           → Dense(5, softmax)
         - PyTorch または TensorFlow/Keras で実装
         - 利点: 時系列パターンを自動学習、推論が高速
         - 欠点: データ量がやや必要

     (c) LSTM（時系列特化）
         - 入力: 同上
         - 構成例:
           LSTM(64) → Dense(5, softmax)
         - 利点: 長い時間依存性を学習可能
         - 欠点: 1D-CNN より遅い、過学習しやすい

     推奨: まず (a) Random Forest を試し、精度不足なら (b) 1D-CNN に移行

  4. 学習・評価
     - 訓練:検証:テスト = 60:20:20 に分割
     - 評価指標: 混同行列、各クラスの適合率・再現率・F1
     - リアルタイム推論速度の確認（15fps 以上を維持できるか）

  5. 統合
     - 学習済みモデルを gesture/models/ に保存
     - detectors/ 内に MLDetector クラスを作成
       - update() で特徴量をバッファに追加
       - バッファが1ウィンドウ分溜まったらモデルで推論
       - 閾値(確信度)以上なら検出イベントを返す
     - main.py で既存の判定器と差し替え（または並列実行で比較）

■ ルールベースとの比較

  項目                ルールベース(現在)     学習モデル
  ──────────────────────────────────────────────────────
  閾値設定            手動(config.py)        データから自動学習
  個人差への対応      閾値を手動調整         追加データで再学習
  複合的な判定        条件の組み合わせ       自動で特徴を組み合わせ
  新しい動作の追加    ロジックを新規実装     データを集めて再学習
  必要データ量        なし                   各動作50〜100回以上
  解釈性              高い(条件が明示的)     低い(ブラックボックス)

■ 必要なパッケージ（実施時に追加インストール）
  - scikit-learn  (Random Forest の場合)
  - torch または tensorflow  (1D-CNN/LSTM の場合)

■ 注意事項
  - 記録時のフレームレートが変動する場合、ウィンドウのフレーム数が
    一定にならない。timestamp_ms でウィンドウを切り出し、
    必要に応じて補間(リサンプリング)する
  - 学習データは本人のみだと他の人で精度が出ない可能性がある
    → 可能なら複数人のデータで学習する
  - リアルタイム推論ではスライディングウィンドウを毎フレームずらして
    推論するため、モデルの推論速度が重要
    → Random Forest や 1D-CNN なら CPU で十分高速
